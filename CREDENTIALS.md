These accounts only exist after the database is migrated and seeded. On a fresh production DB they will not be there until you either:
- Run the test fixture setup, or
- Register them through the public `/register` page and update the role of `admin@test.com` directly in the DB:
  ```sql
  UPDATE users SET role='admin' WHERE email='admin@test.com';
  ```

Then bcrypt-set the password to `000000`:
```sql
UPDATE users
SET password='$2b$10$oTTwqF1h44heijQSaFuVGe3mTa/YOSygtbkBM7zxfOGJDGCe0E/Hi'
WHERE email IN ('admin@test.com','customer@test.com');
```
(That hash was generated from `bcryptjs.hashSync('000000', 10)`.)

## Secrets that are intentionally **not** in this file

The following live in the Render service's Environment tab and the Vercel project's Environment Variables tab — they are **never** committed to git:

- `JWT_SECRET` — autogenerated by Render Blueprint on first deploy
- `DB_HOST`, `DB_USER`, `DB_PASSWORD` — TiDB Cloud connection
- `CLOUDINARY_URL` — contains the API secret
- `SSLCZ_STORE_ID` / `SSLCZ_STORE_PASSWORD` — currently set to SSLCommerz sandbox values; replace with production values for live payments

To rotate any of them: open the Render dashboard → Environment → edit → Save. Render redeploys automatically.

## How the live deploy was set up

See `DEPLOY.md` for the step-by-step. Short version:
1. Database on TiDB Cloud Serverless (https://tidbcloud.com).
2. Image storage on Cloudinary.
3. Backend on Render via the `render.yaml` Blueprint or the API.
4. Frontend on Vercel via GitHub integration after a one-time Login Connection.
